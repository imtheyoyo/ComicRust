## 0. Déjà vérifié automatiquement (pour information)

Le fonctionnement de ComicRack a été relu dans son code source (ComicRack CE) :

- **suivi des modifications** (`ComicStorageBaseSql.Refresh`) : à chaque écriture d'un livre,
  ComicRack augmente `changes.update_counter` et donne la nouvelle valeur au livre ; à chaque
  suppression, il augmente `delete_counter`. ComicRust relit toutes les 5 s ces deux compteurs
  (une requête minuscule), puis seulement les livres modifiés ;
- **listes** : même avec MySQL, ComicRack les garde dans `ComicDb.xml` (base enregistrée « sans
  les livres »), à côté de l'exe si `UseLocalSettings=true` dans `ComicRack.ini`, sinon dans
  `%APPDATA%\cYo\ComicRack Community Edition` ;
- **couverture** (`ComicInfo.FrontCoverPageIndex`) : la page de type « FrontCover » choisie,
  sinon la première page qui n'est pas de type « Autre ».

## Limites connues de la v0.4.0 (ne pas compter comme anomalies)

- **Lecture seule** : ce qui est lu dans ComicRust n'est pas renvoyé à ComicRack (prévu pour une version majeure).
- **Listes intelligentes** : affichées seulement si ComicRack a mémorisé leur contenu dans `ComicDb.xml` ; ComicRust saura les calculer à l'étape suivante (moteur de requêtes).
- Les listes sont relues quand ComicRack réécrit `ComicDb.xml`, ce qu'il ne fait pas à chaque changement.
- En vue tableau, le regroupement ordonne les lignes mais n'affiche pas de titres de groupe.
- Les champs à plusieurs valeurs (« Jim Starlin, Ron Lim ») forment un groupe à eux seuls.
- Les vignettes personnalisées de ComicRack (image de couverture importée) ne sont pas reprises : la couverture est une page du fichier.
